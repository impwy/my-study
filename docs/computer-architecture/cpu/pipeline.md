# 명령어 파이프라인

> 여러 명령어의 서로 다른 처리 단계를 겹쳐 처리량을 높인다.

- 지연시간과 처리량은 다르다.
- 데이터·제어·구조 해저드가 생긴다.
- stall·forwarding·분기 예측으로 대응한다.

<details>
<summary>설명과 꼬리질문 펼치기</summary>

## 설명

명령어를 인출·해석·실행 같은 단계로 나누면 첫 명령이 실행될 때 다음 명령을 해석할 수 있다. 이상적으로는 파이프라인이 찬 뒤 매 클록 결과를 내지만 단계 불균형과 의존성 때문에 그대로 달성되지 않는다. 다른 명령의 결과가 아직 없거나 분기 방향을 모르면 기다리거나 잘못된 작업을 취소한다.

## 주의점

단계를 늘린 만큼 성능이 항상 배로 좋아지는 것은 아니다. 하나의 명령어가 끝나는 시간과 연속 결과가 나오는 간격을 구분한다.

## 꼬리질문

1. 분기를 잘못 예측하면 이미 시작한 명령어는 왜 취소해야 할까?
2. 파이프라인의 첫 명령 지연과 연속 명령 처리율은 어떻게 다를까?
3. 명령 간 데이터 의존성이나 분기 실패를 넣으면 이상적인 사이클 계산이 어떻게 달라질까?
