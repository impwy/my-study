# 임계 구역과 동기화

> 공유 상태의 불변식이 깨지지 않도록 동시에 들어오는 실행을 제어한다.

- 경쟁 상태는 실행 순서에 결과가 의존하는 문제다.
- 상호 배제·진행·한정 대기를 고려한다.
- 같은 보호 규칙을 모든 접근이 따라야 한다.

<details>
<summary>설명과 예제 펼치기</summary>

## 설명

각 작업이 따로 읽고 계산한 뒤 쓰면 다른 작업의 변경을 덮어쓸 수 있다. 락은 임계 구역을 한 번에 하나만 실행하게 한다. 세마포어는 허용 수를 관리하고 조건 대기는 상태가 만족될 때까지 효율적으로 기다린다. 로컬 락은 다른 프로세스·서버 인스턴스의 접근까지 막지 않는다.

## Java 예제

```java
static class Counter {
    private int value;

    synchronized void increment() {
        value++;
    }

    synchronized int get() {
        return value;
    }
}
```

## 주의점

변수 쓰기 한 줄만 보호하고 그 전의 판단을 밖에 두면 검사-실행 경쟁이 남을 수 있다.

## 꼬리질문

1. 읽기와 쓰기 사이의 계산도 임계 구역에 포함해야 하는 이유는?
2. value를 읽는 것과 쓰는 것만 따로 잠그면 증가 하나가 사라지는 실행 순서는 무엇일까?
3. 모든 쓰기를 잠가도 읽기를 잠그지 않는다면 어떤 가시성 문제가 남을까?
