# SIP: 통화의 시작·변경·종료를 제어하는 신호

> SIP는 누구와 어떤 조건으로 통화할지 제어하는 시그널링 프로토콜이며, 실제 음성은 별도의 미디어 경로로 흐른다.

- **역할:** SIP는 Session Initiation Protocol로, 세션을 생성·변경·종료한다.
- **연결:** 전화 연동 사업자의 SIP 트렁크를 통해 전화번호로 들어온 통화를 AI 음성 서비스로 연결할 수 있다.
- **주의:** 통화 연결 성공과 음성 전달 성공은 별도로 확인해야 한다.

## 설명

SIP는 애플리케이션 계층의 통화 제어 규약이다. 통화 초대에는 `INVITE`, 수락에는 `200 OK`, 수락 확인에는 `ACK`, 성립된 통화의 종료에는 `BYE` 같은 메시지를 사용한다. 이는 이해를 위한 대표 흐름이며, 실제 통화에는 임시 응답·인증·재전송 등 추가 절차가 있다.

SIP 메시지는 SDP 같은 세션 설명을 담아 음성 코덱, 미디어 주소·포트 등을 협의할 수 있다. 협의가 끝나면 실제 음성은 [RTP](rtp.md) 또는 [SRTP](srtp.md) 같은 미디어 전송 방식으로 전달한다.

| 경로 | 전달하는 내용 |
| --- | --- |
| SIP 시그널링 | 통화 초대·수락·종료와 세션 조건 |
| 미디어 경로 | 고객 음성과 AI 응답 음성 |
| 애플리케이션 제어 연결 | 업무 API 호출, 상담 정책, 통화 이벤트 등 |

AI 고객센터에서는 `고객 휴대폰 ↔ 전화망·전화 연동 사업자 ↔ AI 음성 서비스`로 연결할 수 있다. OpenAI Realtime API의 SIP 연동은 수신 웹훅으로 애플리케이션에 통화를 알리고, 애플리케이션이 수락·거절을 결정하도록 지원한다. 이후 별도 WebSocket으로 같은 세션을 관찰·제어할 수 있다. **웹훅과 WebSocket 제어 연결은 이 서비스의 연동 방식이며, SIP 자체의 필수 구성은 아니다.**

음성을 서버가 직접 받아 처리하는 방식과의 관계는 [AI 전화 상담의 음성 파이프라인](ai-call-voice-pipeline.md)을 참고한다.

## 주의점

- SIP는 음성 인식·답변 생성·음성 합성 기능을 제공하지 않는다.
- SIP 응답이 정상이어도 미디어 주소·포트나 방화벽 설정이 맞지 않으면 음성이 들리지 않거나 한 방향만 들릴 수 있다.
- SIP 연결을 TLS로 보호했다고 실제 음성도 암호화되는 것은 아니다. 미디어 보호에는 SRTP 등 별도 구성이 필요하다.

## 꼬리질문

1. 통화 설정 신호와 실제 음성 데이터를 서로 다른 경로로 구분하는 이유는 무엇인가?
2. AI 고객센터에 전화가 연결됐는데 양쪽 모두 소리가 들리지 않는다면, SIP 수락 이후 어떤 미디어 정보를 확인해야 하는가?
3. SIP를 TLS로 연결한 환경에서도 음성이 노출될 수 있는 조건은 무엇이며, 어떤 구간의 보호를 추가로 확인해야 하는가?
