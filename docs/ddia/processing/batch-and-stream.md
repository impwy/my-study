# 배치와 스트림 처리

> 유한한 입력 묶음의 처리와 계속 도착하는 이벤트의 처리를 완료·재시작·지연 기준으로 비교한다.

- 배치는 묶음의 완료를 정의한다.
- 스트림은 지속되는 입력·진행 위치를 다룬다.
- 재처리와 중복 효과를 설계한다.

## 설명

Spring Batch의 chunk 방식은 일정 수의 입력을 읽고 변환·기록한 뒤 커밋하며 재시작에 필요한 상태를 관리할 수 있다. 스트림은 계속 도착하는 로그·이벤트를 처리하고 위치·지연·실패를 추적한다. 배치로 주기 집계를 만들거나 스트림으로 파생 데이터를 갱신할 수 있다. 선택은 필요한 최신성·처리량·정확성·운영 비용에 달려 있다. 예를 들어 (A,+2)·(A,+2)·(B,+3)을 처리할 때 이벤트 ID A의 재전달을 제외하면 합계는 5다.

## 주의점

DB에 저장했다는 사실과 외부 Writer 효과가 같은 트랜잭션으로 묶였는지는 따로 확인한다. chunk 수만 늘려 항상 성능이 좋아지지 않는다.

## 꼬리질문

1. 스트림으로 갱신한 결과를 주기 배치로 대사하면 어떤 오류를 발견할 수 있는가?
2. 처리한 이벤트 ID를 기록하면 A가 재전달될 때 어떤 중복 합산을 막을까?
3. 운영 스트림의 상태와 원본 로그를 다시 계산한 배치 결과가 다르면 어떤 누락·지연·정정 이벤트를 조사할까?
