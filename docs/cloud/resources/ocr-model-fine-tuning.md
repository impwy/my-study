# OCR 모델의 학습·추론과 신분증 정보 추출

> OCR은 이미지의 문자를 텍스트로 변환하는 작업이며 파인튜닝은 기존 모델을 특정 데이터로 추가 학습하는 방법이다.

- OCR은 Optical Character Recognition, 광학 문자 인식이다.
- 파인튜닝은 사전 학습 모델의 파라미터를 특정 작업에 맞춰 조정한다.
- 문자 추출·필드 해석·신원 확인은 서로 다른 검증 대상이다.

## 설명

OCR은 이미지나 스캔 문서 속 문자를 컴퓨터가 처리할 수 있는 텍스트로 변환한다. 이를 구현하는 데 신경망 모델을 사용할 수 있지만 OCR의 풀네임은 “광학신경망모델”이 아니다. “OCR 모델 파인튜닝을 통한 신분증 인식 모델 개발”로 표현하면 작업과 방법이 구분된다.

파인튜닝은 기존 모델을 출발점으로 작업에 맞는 데이터로 추가 학습한다. 신분증 이미지와 정답 텍스트·필드 정보를 학습 자료로 삼는 것이 가능한 예다. 학습은 모델을 조정하는 작업이고 추론은 준비된 모델로 새 입력의 결과를 계산하는 작업이다. 서비스의 컴퓨팅 리소스를 검토할 때 두 작업을 구분한다. 프롬프트 문구를 바꾸는 프롬프트 개선과 학습으로 모델 파라미터를 조정하는 작업도 다르다.

```text
문서 이미지 → 문서·문자 영역 검출 → 문자 인식 → 이름·발급일 등 필드 해석
```

이 흐름은 개념 예시이며 모든 OCR 시스템이 같은 구성인 것은 아니다. 특정 문자를 맞혔는지와 이름·발급일 필드를 올바르게 추출했는지는 별도 평가다. 실무 적용을 판단할 때는 인식 결과, 처리 지연, 실패 시 재촬영·재검토를 함께 확인한다.

## 주의점

문자를 읽었다고 문서의 진위나 사진을 제출한 사람의 신원까지 확인되는 것은 아니다. 흐림·반사·기울기·문서 양식 변경을 평가 사례로 포함하고 학습에 사용한 이미지로만 성능을 판단하지 않는다. 신분증 예시는 실제 개인정보 대신 합성·비식별 자료로 설명한다. Bedrock과 AI Agent의 서비스 역할은 [별도 문서](../../aws/operations/bedrock-ai-applications.md)에서 확인한다.

## 꼬리질문

1. OCR이라는 작업과 신경망·파인튜닝이라는 구현·학습 방법이 서로 다른 구분인 이유는?
2. 발급일 문자를 읽었지만 이름 필드에 넣었다면 문자 인식과 필드 추출 중 어떤 평가가 필요한가?
3. 학습 이미지의 정확도가 높아도 새로운 양식·촬영 환경에서 성능을 보장하지 못하는 이유는?
