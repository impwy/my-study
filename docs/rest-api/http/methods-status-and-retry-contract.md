# HTTP 메서드·상태 코드와 재시도 계약

> 메서드는 작업의 의미를, 상태 코드는 처리 결과를 표현하며 둘을 함께 설계해야 한다.

- GET은 조회, PUT은 대상 리소스 상태의 생성·대체를 표현한다.
- 멱등성은 반복 요청의 의도된 효과에 관한 계약이다.
- 201·202·204는 생성·접수·본문 없는 성공을 구별한다.

## 설명

GET 같은 안전한 메서드는 사용자가 요청한 변경 작업을 수행하지 않는다. PUT·DELETE와 안전한 메서드는 멱등하며, 같은 요청을 반복해도 의도된 효과가 한 번의 요청과 같아야 한다. 재요청의 상태 코드까지 같아야 한다는 뜻은 아니다. POST는 처리 의미가 다양하므로 중복 실행을 막는 별도 계약 없이 무조건 재시도하지 않는다.

생성 완료는 201과 생성된 리소스의 위치로 설명할 수 있다. 202는 요청을 접수했지만 처리가 아직 끝나지 않았음을 뜻하며 진행 상태를 확인할 방법을 제공한다. 204에는 응답 본문이 없으므로 항상 JSON을 파싱하는 클라이언트와 계약이 맞지 않는다.

## 주의점

타임아웃은 서버의 미처리를 보장하지 않는다. 멱등 요청이어도 재시도 횟수·간격·기한을 제한하고 업무 부수 효과까지 점검한다.

## 꼬리질문

1. 동일한 DELETE에서 첫 응답 204, 두 번째 응답 404여도 멱등일 수 있는 이유는 무엇일까?
2. 결제 POST가 타임아웃일 때 바로 다시 보내면 어떤 문제가 생길까?
3. 202 응답을 받은 클라이언트가 완료를 알기 위해 필요한 추가 계약은 무엇일까?
