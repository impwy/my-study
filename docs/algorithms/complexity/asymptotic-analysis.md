# 점근 분석

> 입력 크기가 커질 때 연산 횟수가 어떻게 증가하는지 비교한다.

- 입력 크기 n을 먼저 정의한다.
- 최악·평균·최선은 서로 다른 분석이다.
- 실행 시간 측정과 증가율 분석을 함께 본다.

## 설명

O는 증가율의 상한, Ω는 하한, Θ는 같은 증가율의 상·하한이다. 상수와 낮은 차수 항을 생략해 규모가 커졌을 때의 차이를 드러낸다. 이중 반복문이어도 안쪽 구간이 매번 절반으로 줄면 무조건 O(n²)는 아니다. 각 반복에서 실제로 방문하는 원소 수를 합산한다.

## Java 예제

```java
static long pairComparisons(int n) {
    long count = 0;
    for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) count++;
    return count;
} // n=4 → 6, n=8 → 28; n(n-1)/2 = O(n²)
```

## 주의점

O(n)은 “항상 n번”이나 “정확히 n초”라는 뜻이 아니다. JVM 워밍업·입출력·캐시가 실제 측정에 영향을 준다.

## 꼬리질문

1. 배열을 정렬한 뒤 이진 탐색을 한 번 하는 전체 비용은 왜 O(log n)이 아닐까?
2. 예제의 반복 횟수를 합으로 쓰면 왜 n(n-1)/2가 될까?
3. n이 작을 때 실행 시간이 더 짧다는 측정만으로 점근 복잡도가 더 좋다고 결론 낼 수 있을까?
