# S3 객체와 저장소 선택

> S3는 파일을 객체 키로 저장하는 서비스이며, 백엔드는 DB에 파일 식별자를 기록하고 권한에 따라 파일 접근을 제공할 수 있다.

- **구조:** 버킷·객체 키·메타데이터를 구분한다.
- **역할:** 이미지·첨부파일·배포 산출물 등을 보관하며 EC2의 블록 저장소와 접근 모델이 다르다.
- **관리:** 버전 관리·수명 주기·접근 정책을 설계한다.

## 설명

S3 객체는 키와 데이터·메타데이터로 관리하며 API로 접근한다. EBS는 서버의 블록 장치, EFS는 공유 파일 접근을 제공하는 다른 모델이다. 필요한 업데이트·공유·용량·접근 방식에 따라 고른다. S3의 버전 관리와 수명 주기로 변경 복구·보존·저장 클래스를 관리할 수 있다. 공개 접근은 버킷 정책과 차단 설정을 명확히 확인한다.

사진이 포함된 게시글을 등록하는 백엔드에서는 다음처럼 역할을 나눌 수 있다.

1. 브라우저가 EC2의 백엔드에 게시글과 사진을 보낸다.
2. 백엔드가 사용자 권한을 확인하고 사진을 S3에 저장한다.
3. DB에는 제목·본문·작성자와 `posts/123/photo.jpg` 같은 객체 키를 저장한다.
4. 사진을 읽을 때 해당 객체에 접근하는 경로를 제공한다.

비공개 파일은 백엔드가 사용자 권한을 확인한 뒤 유효기간이 있는 presigned URL을 발급하도록 구성할 수 있다. 브라우저가 이 URL로 S3에 직접 업로드하면 파일 데이터가 EC2를 거치지 않는 구조도 가능하다. URL은 특정 작업을 허용하는 임시 접근 수단이며 소지한 사람이 사용할 수 있다.

일반적인 S3 버킷은 VPC의 서브넷에 배치하는 자원이 아니다. EC2에서 API로 접근한다. S3에는 사용자 파일뿐 아니라 배포용 JAR도 보관할 수 있지만, 파일을 저장하는 것만으로 백엔드가 실행되지는 않는다.

## 주의점

객체 키의 `/`는 접두어를 나누는 표현이며 일반 파일 시스템의 디렉터리와 같지 않다. 만료되는 presigned URL 자체를 영구 파일 식별자로 저장하기보다는 객체 키를 보관하고 필요한 시점에 URL을 발급한다. 백업 업로드와 복구 가능성은 별개이므로 권한·버전·암호화 키·보존 정책을 함께 확인한다.
